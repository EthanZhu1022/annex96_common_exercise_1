\chapter{Introduction}\label{ch:intro}

Modern homes are no longer only passive electricity consumers. They may include
solar panels, batteries, heating and cooling equipment, and other controllable
devices. Coordinating these resources across a community can move electricity
use away from peak periods and make the combined load follow a desired grid
profile. The difficulty is that each building has different demand and
flexibility, while control performance is evaluated for the whole portfolio.


Building energy research has therefore increasingly moved from fixed
rule-based control toward reinforcement learning and multi-agent coordination
\cite{charbonnier2025,wilk2024}. This project uses CityLearn, an open simulation
environment that provides a standardized and reproducible way to compare
building-control algorithms \cite{citylearn2020,citylearnv2}. The experiment
follows the IEA EBC Annex 96 Common Exercise 1 benchmark: 25 single-family homes
are controlled as one portfolio to track a daily reference load profile using
battery and HVAC flexibility. Evaluation covers CV-RMSE, NMBE, indoor comfort
(measured as temperature deviation multiplied by duration and averaged per
building per test day), energy use, peak demand, ramping, load factor, and
fairness. Vermont uses
January for training and February for testing, while Texas uses August and
September.


The first progress report, completed prior to this report, established a
reproducible CityLearn experimental pipeline based on the IEA EBC Annex 96
Common Exercise 1 (CE1) benchmark. It compared rule-based control, independent
reinforcement learning, standard MAPPO, grouped MAPPO, and several communication
modules for a portfolio of 25 homes. The main result was that grouped
cooperative control was substantially stronger than the fixed rule-based
baseline, while the choice of communication structure materially changed load
tracking and thermal comfort. Among the tested communication directions,
TarMAC showed the greatest potential. The previous report also identified
several unresolved problems: the original TarMAC communication method did not
fully use each agent's own information, and K-means grouping was treated as a
fixed preprocessing step rather than an independent research variable. Preliminary
experiments showed that K-means produced weak groups, which directly affected
the subsequent MAPPO training. The current MAPPO model depends strongly on the
quality of the fixed grouping, and this quality depends on both the grouping
method and the selected grouping features.


The core research question of this second report is:

In the CityLearn portfolio load-tracking task, how should communication,
building grouping methods, and grouping features be designed to improve MARL?
Alternatively, is there a method that can reduce the model's dependence on a
fixed grouping?


\noindent\textbf{The main innovation of this work} is a Soft Router for grouped
MAPPO that dynamically selects a complete actor for each building according to
its current state, relaxing the permanent building-to-actor assignment imposed
by fixed grouping.


This second report addresses those problems in four connected studies. First,
it introduces \emph{TarMAC Hybrid}. It reduces each agent's own information to
a smaller and clearer form and uses ReLU to keep the more useful parts. This
shortened information is then combined with information received from other
agents, while the original information is retained. Second, the report compares
K-means, Gaussian mixture models (GMM), Ward agglomerative clustering, and a
balanced spectral method. Third, it studies both the number and composition of
grouping features and ultimately identifies a compact three-feature design,
denoted 3fA:
battery energy-storage capacity, mean heating demand, and mean non-shiftable
load. Finally, it develops a soft router. In simple terms, this is a small
neural-network selector for each building. At every time step, it examines the
building's current condition and gives each available actor a selection
probability. These probabilities help decide which actor should guide the
building's action. This tests whether a building can use different actors at
different times instead of always depending on the actor assigned by its fixed
group.
